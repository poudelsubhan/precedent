# Precedent build audit

Audited September 12, 2026 against `precedent-phase-plan.md` and `precedent-project-and-demo.md`.

**The full phase plan is not complete.** The repository implements a working foundation and several inspectable demo beats. It does not yet establish the complete attack → intervention → autonomous recovery → verified learning → fresh-session reuse loop required by final acceptance.

“Implemented” below means code exists and was inspected. “Verified” names a test or observed runtime result. Neither substitutes for the plan’s stronger end-to-end acceptance checks.

## Verification

The initial eight tests passed. The updated suite adds four frontend request/contract checks, for twelve tests total. Workspace type checking and the production build passed. Repository formatting and `git diff --check` also passed. Browser observations above test the real local UI and services. The responsive console was checked at 390px with no document-level horizontal overflow. These checks do not certify full WCAG conformance, the entire phase plan, or production security.

## Priority to reach final acceptance

1. Build the real isolated range and independent traffic/verifier path, including snapshot/reset variants.
2. Make graph relationships and eligible verified history change recovery selection; persist immutable evidence, query parameters, and versions at evaluation.
3. Complete and record one autonomous Qoder recovery, trusted case promotion, and fresh-session reuse under both matching and changed conditions.
4. Add broker/graph integration and fault-injection proofs, durable run export, recorded replay/video, and the final submission package.

The phase plan remains the target. Its boxes have not been checked merely because similarly named functions exist.
